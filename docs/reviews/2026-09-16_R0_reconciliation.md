Origin and harm are now separate axes: origin ∈ {clean, N_cov, N_struct, G, S_in_span, S_support, mixture, constructed, unknown}, harm ∈ {benign, harmful, undefined}. A clean rare event can be harmful (S_in_span, K up) and a mild corruption benign (N_cov at κ ≈ 2). The old single label conflated the two.

## 3. Contradictions found, and their resolutions

1. **C4 conditioning.** Proposal Table 1: "Primary: among strong-alarm cells, AUROC/AUPRC for K ≥ κ_m". `EXPERIMENT_DESIGN.md` §I.3: "C4 alarm ranks consequence, *conditional on alarm*". `TODO.md`: "C4 primary = pooled ranking + designed dissociation, not within-(family, severity) strata". `REVIEW_PROMPTS.md` §B D.3 and the red-flag list: a pooled alarm–consequence correlation without severity strata is a finding. Plan §8 R3: all-cell AUROC primary. **Resolution:** primary = AUROC for K ≥ κ_m across all held-out cells with a declared weighting scheme (an operational ranking question: does the alarm order the cells a physicist would want flagged?); conditional strong-alarm analysis is secondary triage; family/severity breakdowns and the designed dissociation are mandatory companions because pooled association alone cannot establish the mechanism; a pooled *Pearson/Spearman correlation* is still not a primary endpoint. The review prompts now distinguish the operational ranking from the mechanism check instead of forbidding pooling outright.
2. **Claim priority.** Proposal: C2 with two co-primary endpoint families; C4 primary on waveforms. `TODO.md`: "choose the one claim to lead with". §8.2: C2 and C4 central, one primary endpoint each. **Resolution:** C2 primary = ΔF1 (operational family); the mechanism family (displacement, retention, principal angles, layer profile) is secondary/descriptive. C4 as in item 1. C1/C3 supporting; C0/C5 mechanistic, bounded.
3. **E namespace.** See §2. New code never uses a bare "E".
4. **Pre-registration location.** `TODO.md` places it in the external experiment repository (`docs/plans/oracle/PREREGISTRATION.md`); plan §1 places it here. **Resolution:** an *unfrozen draft* `docs/PREREGISTRATION.md` lives here with `status: DRAFT — unfrozen, no hash`; the external dependency is recorded in it; `protocol.mode` reads `protocol/frozen/<part>.json` and refuses confirmatory mode while none exists. No hash is fabricated.
5. **Phase 2 SPINE vs Panda.** Plan §7.3 says the proposal still reads "SPINE/Graph-SPICE transfer"; the tex already reads "Panda scale transfer … SPINE remains the later domain-specific extension". **Resolved earlier; §7.3 is stale** and is marked so.
6. **Abstention.** Proposal §4 C2: split-conformal nonconformity. `EXPERIMENT_DESIGN.md` §III.3.4: conformal on classifier margin fails (dev AUROC 0.25); feature-space Mahalanobis works (0.71). **Resolution:** abstention is a feature-novelty score (Mahalanobis in the reference z-metric; Fisher-rank drop as the mechanism trigger); a conformal calibration only sets its threshold and only under exchangeability of calibration and deployment *clean* windows. It does not guarantee rejection of arbitrary unknown families; unknown-family detection is evaluated empirically (AUROC, risk–coverage) and retained coverage is a reporting point, not a threshold tuned on confirmatory labels.
7. **Noise-only statistics.** `EXPERIMENT_DESIGN.md` §III.1/§III.3.3 and the 6 Sep report present the noise-only discriminator as the lookup's foundation; §8.1 says it belongs to the strong generic baseline. **Resolution:** noise-only (random-trigger) records are acquisition-quality features; they are *operational* only where the acquisition supplies them (Tier 1 simulator: yes; TIDMAD: 208 no-injection files, yes; Prometheus hit-level: no — privileged). Where operational they are in the all-generic arm, and a noise-only ablation arm is run so that attribution gains are assigned to their source. Success of the lookup on Σ-type cells is therefore *not* evidence for internal representations.
8. **Paired twins are replay-side information.** Every Δz statistic in `statistics.cell_statistics` is computed against the paired clean twin (the same event through the reference cell). That is available in simulation and in the designed-contrast machinery, not at alarm time in deployment. **Resolution:** the feature-availability manifest (`protocol.availability`) labels twin-based features `evaluation_only`; alarm-time arms consume only reference-fitted statistics of the *observed* window (per-hook Mahalanobis, energy splits about the reference mean, out-of-span fraction from the residual, noise-only features). The 13/14 table is a replay diagnostic, correctly described as development evidence of the *signatures*, not of alarm-time attribution.
9. **Tier-1 consequence variable.** Arms plan/TODO: "whitened reconstruction error on the trace"; code: mean |ŷ − truth| on the planted (amplitude, t0, τ). **Resolution:** K_phys (physical-parameter error against evaluation-only truth; amplitude first) is the independent physical endpoint; the whitened residual is the diagnostic K_diag. Both are reported; K_diag is never the sole demonstration of scientific advantage, because it shares the training objective's weighting.
10. **Assumed vs realised covariance.** Operational statistics use Σ̂ (`subject.sigma_hat`); the generator's implied/realised Σ is evaluation-only. `rewhiten` estimates Σ from noise-only records (operational where those are). The manifest names each. Exact full-covariance Gaussian likelihood (Kronecker Σ̂ here), diagonal inverse-PSD approximation (the tidmad objective) and quadratic diagnostics under non-Gaussian noise (`ArtifactInjector` tails) are three different objects; the draft pre-registration says which one each arm uses.
11. **Repository layout.** Plan §1 names `src/oracle_diag/` and `experiments/`; neither exists. `src/latent_monitor/` is the implemented diagnostics layer (hooks, projectors, statistics, lookup, designed contrasts, adjustments) and now carries `protocol/`. **Resolution:** plan §1 is annotated; WP names are kept.
12. **README testbeds.** README says "two complementary testbeds are planned" (NuBench + waveforms); the canonical design has three tiers and three realism arms. README updated.
13. **Evidence level of "13/14".** Reported at C = 8, N = 256, 60 evaluation events, 100 noise records, thresholds at the reference q99 from a 200-draw bootstrap, single model. It is development evidence; it was never at 1 % FAR with ≥ 100 clean calibration windows, event groups were not split (the same event ids serve as reference-vs-reference null and as evaluation), and no family was held out from the lookup's design. None of this is hidden in the artifact, but the README's "validated development pilot" wording invited the upgrade; corrected.
14. **Legacy conditional AUROC.** `consequence_auroc_given_alarm` conditions on the top-10 % per-event alarm *within one cell* and labels harm as "worse than the twin", not K ≥ κ_m. It stays as a documented legacy secondary; the new endpoint replaces it as primary.
