## What this iteration implements

1. **Geometry reader** — `load_wcte_geometry(config_path_or_npz)` accepts either the JSON
   pointer (reads `geometry_definitions.npz_file_path`, resolves it relative to the pointer,
   verifies the pointer sha256 against the pinned value when the file is named
   `WCTE_geom_config.json` or when `expected_config_sha256` is given) or the `.npz` directly
   (verified against the pinned prefix). It returns a frozen, validated `DetectorGeometry`:
   positions in m (from `positions_mm`), unit inward directions, `surfaces`, `pmt_id` (1…1995),
   raw `mpmt_id`, 1-based `pmt_id_in_mpmt`, dense `module_index` 0…104, sorted `module_ids`,
   module centres (derived), `radius_m`, `height_m`, `sensor_radius_m`, a layout-only
   `digest`, `source_path`, `source_sha256` (npz file), `config_sha256`, `synthetic`.
   Validation refuses: wrong sensor/module/PMT counts, a module with missing PMTs, duplicate
   or non-increasing module ids, wrong surface counts or unknown surface labels (override with
   `surface_map`), non-unique/out-of-range `pmt_id`, `pmt_id_in_mpmt` not exactly 1..19 per
   module (0-based ids are refused), non-finite arrays, non-unit directions, non-positive
   scalars, and sensor z outside the detector. **Sparse `mpmt_id` is accepted**: id 45 is
   absent in the real map and `module_ids_contiguous` is False; nothing indexes modules by raw
   id. `from_synthetic(schema)` builds the schema-identical fixture (tests only) and can be
   told to build invalid variants so the refusals are testable.
2. **Event generator** (§3.5.3 photon bombs) — isotropic point source; vertex uniform in
   volume in the 80 % fiducial cylinder; emission at t = 0; photon yield log-uniform in
   `[y_lo, y_hi]` from the config; wavelength sampled per PMT from the configured spectrum
   (uniform 300–600 nm, a **synthetic** stand-in for the PMT reference spectrum, labelled in
   the manifest); QE from a configured sampleable curve; prompt transport with no scattering,
   reflection or absorption beyond `exp(-d/λ)`; per-PMT expected charge
   `μ_p = Y · QE(λ_p) · CE · Ω_p/(4π) · exp(-d_p/λ)`. All values that are pending the
   detectability check are config parameters, not constants.
3. **Synthetic unrepaired readout** — `readout_synthetic_unrepaired(state, draws, geometry,
   cfg)`: Poisson detection on `μ_p` (exact inversion from shared uniforms), dark counts per
   run window added to the same charge, single-photon charge smearing
   `q = n + √n·σ_spe·z` clipped at 0, the state's per-PMT gain applied to the charge **before**
   the threshold, the fixed threshold in PE, and the walk curve imported from
   `noise_module_lucid.response.leading_edge_time` (never forked). Gains are the product of the
   existing F1/F3/F2′ factors, each clipped to [0.5, 1.5] separately with counts recorded in
   `DetectorState.clipped` and in the run manifest (`state_clipped`).
4. **Nominal twin** — for every event `generate_run(..., with_twin=True)` also writes the
   nominal readout (all gains 1, λ = λ0) through the existing private contract
   `nominal_twin(draws, geometry, readout, arm="oracle_nominal_twin")`, which raises
   `PermissionError` for any other arm. The twin reuses the same `SensorDraws`; only the state
   (gain factors and λ) changes.
5. **Runs and storage** — the existing `COHORTS`/`make_runs`/`RunSpec`/`DetectorState`
   structure: training and development runs of 1000 events, probe/robustness runs of 50
   events, every event of a run sharing one state (`RunSpec.state`), event ids from the
   registered `lucid/` ranges. `generate_events` yields one `GeneratedRun` at a time (memory
   holds one run); `write_generated_run` writes `hits.npz` (CSR-like sparse: event ids,
   offsets, PMT indices, charges, times), `twin_hits.npz` when the twin is generated,
   `events.npz` (per-event truth: vertex, yield, total expected PE — needed for the probe
   targets), `manifest.json` and `SHA256SUMS`. The manifest records run spans, law/setting,
   per-run state hash, event-id hash, **geometry sha256**, geometry source/config hashes, the
   generator-config sha256, the readout label, the code SHA, `reported_results=false`,
   the yield range and its status, the fiducial fraction, threshold, spectrum label, clipped
   counts and the twin flag.
6. **1000-event benchmark** — `benchmark_generation` (CLI below) times 1000 events at the
   default yield range with the nominal twin, records peak RSS and sparse-store bytes, and
   returns the §3.5.3 per-yield-tercile table (hit PMTs, module charge, hit fraction).

## Formulas and approximations

- **Solid angle.** `Ω_p/(4π)` with the exact on-axis disc solid angle times obliquity:
  `Ω_p = 2π(1 − d/√(d²+r²))·|cosθ|`, i.e. `πr²cosθ/d²` for `d ≫ r`; the tilt correction is
  O((r/d)²). With `|vertex| ≤ 0.8` of the detector, `d ≥ 0.2R = 0.315 m` and `r = 0.04 m`, so
  the error is below ~2 %.
- **Expected charge.** `μ_p = Y · QE(λ_p) · CE · Ω_p/(4π) · exp(−d_p/λ)`, with `λ` the run
  state's attenuation length (F2/λ0) and `QE(λ_p)` from the config spectrum and QE curve.
- **Photon count.** Exact Poisson draw from keyed uniforms:
  `n_i = #{k : Σ_{j≤k} −ln u_ij ≤ μ_i}` (arrival times of a unit-rate Poisson process). The
  same `u` matrix mapped through the drifted and nominal `μ` gives the twin correlated photon
  counts; for gains-only factors `μ` is identical and the counts are identical.
- **Charge.** `q = n_photon + n_dark`, then `q ← max(0, q + √q·σ_spe·z)` with one keyed normal
  per PMT; then `q ← q · gain_p` (state gains, already clipped per factor).
- **Threshold and walk.** `hit = isfinite(walk)` with
  `walk = leading_edge_time(q, threshold_pe·mv_per_pe)`; the readout time is
  `t = d·n_group/c + σ_tts·z_transit + (walk − walk_cal)`, where `walk_cal` is the same walk
  curve at the training-time `walk_calibration_pe`. With `threshold_pe == walk_calibration_pe`
  (the default) the residual is exactly zero; a config that moves the threshold gets the real
  charge-dependent time-walk from the PMT primitive.
- **Approximations, stated.** (a) The event is generated analytically from `μ_p`, not by
  transporting individual photons through LUCiD; the prompt, non-scattering transport is
  exactly `exp(−d/λ)`. (b) All prompt photons on a sensor arrive at the same time
  (`d·n_group/c`); the only time spread is the config transit-time Gaussian. (c) Dark counts are
  smeared with the signal charge. (d) The QE curve, the CE, the spectrum and all front-end
  levels are **synthetic placeholders** until the PMT branch is merged. (e) The walk primitive
  is the preset's bi-exponential SPE; its `mv_per_pe` is a placeholder like the rest.
- **Gain clipping.** Each factor is clipped separately to [0.5, 1.5]; the number of clipped
  module/PMT/gradient factors per run is recorded (never silently dropped).

## Ambiguities (for the lead)

1. **Two "geometry shas".** The manifest keeps `geometry_sha256` = the layout `digest`
   (existing `verify_manifest` contract) and records the file hashes separately as
   `geometry_source_sha256` (the npz, expected prefix `0a75b035`) and `geometry_config_sha256`
   (the pointer, `9943d602…`). Say if a registered field should carry the file hash instead.
2. **`surfaces` encoding.** We require `top`/`barrel`/`bottom` labels (case-insensitive) and
   offer `surface_map` for other encodings. The real npz dtype was not inspectable on this Mac;
   if it stores integers, the host operator must pass the mapping once.
3. **Twin storage and access.** `twin_hits.npz` sits beside `hits.npz`; the oracle-only rule is
   enforced by `nominal_twin` (API), not by the filesystem. If the lead wants filesystem
   separation, write the twin under an oracle-only directory instead.
4. **"Same photon draws" with a changed λ.** We share the *underlying Poisson uniforms* (so
   counts are correlated and identical for gains-only factors), not the realised counts, which
   cannot be identical when λ changes. This is our reading of "same photon, SPE, transit-time
   and dark-count draws (keyed RNG)".
5. **Dark counts.** One keyed Poisson draw per event (state-independent), added to the signal
   before smearing; the 4.2 kHz rate is the `noise_module_lucid.presets.LUCID_DARK_RATE_HZ`
   convention, config-driven.
6. **Event truth arrays.** `events.npz` (vertex, yield, expected PE) is an addition beyond
   "hits only", required by the §3.5.6 vertex/yield probes; it is hashed in the manifest.
7. **Robustness ID range.** `lucid/robustness` 220000–229999 remains a WP4b extension (v3 §6 has
   no range); unchanged from the previous iteration.
8. **R11b setting.** Still interpreted as the F2 attenuation `a` of the co-varying law (previous
   iteration's ambiguity; unchanged).
9. **Second pending input for a cohort run.** The per-run writer is implemented; the cohort
   driver is a short host-side loop (above), not a module entry point, to keep this WP focused.

## Engineering decisions (one line each)

- Geometry is path-configured, layout-hashed and never embedded; LUCiD data stays on the host.
- `mpmt_id` is kept raw and dense `module_index` is derived from it, so the absent id 45 cannot
  corrupt indexing.
- The synthetic fixture reuses the real scalar values and counts, so the code path (not just the
  shape) is exercised locally.
- The event generator is analytic in `μ_p` rather than a photon transport: exact for the
  runbook's prompt/no-scattering/attenuation-only model and cheap enough for the 48 h cap.
- Poisson counts are drawn from shared uniforms by exact arrival-time inversion, so the twin
  shares the photon draw across λ.
- Gains are applied before the threshold and the walk is the imported PMT primitive, not a copy.
- Sparse storage stays CSR-like; float32 charges/times, int32 PMT indices, int64 offsets.
- The benchmark reports the process peak RSS and the sparse-store bytes, not a modelled number.
- `λ0` is frozen to the module constant and the config is checked against it, so a silent
  mismatch cannot change F2 between generation and detection.
